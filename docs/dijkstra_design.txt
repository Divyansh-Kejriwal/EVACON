# EVACON — Dijkstra Routing Notes

## Goal

- Build a first version of Dijkstra's algorithm for EVACON.

The function should eventually answer:
Given a network, a starting node, a destination, and a movement speed, what is the fastest path and how long does it take?

Function
` def dijkstra(adjacency, start, destination, speed):
    pass `

What the function should return

If a route exists:
(path, total_time)
Example:
([A, B, C, exit1], 15.0)
If the destination is unreachable:
(None, infinity)

Dijkstra — Build It Step by Step

Step 1 — State we need
Inside the function:
distances = {}
previous = {}
visited = []
distances
Stores the best-known travel time to each node.

Conceptually:
A → 0
B → infinity
C → infinity
Exit → infinity
The starting node gets 0.

Every other node initially gets:
float("inf")

Step 2 — Initialize distances
Do not hard-code node names.
Use the adjacency argument.

Hint:
Iterate through the keys of adjacency.

You need to produce something equivalent to:
distances = {
    "A": 0,
    "B": float("inf"),
    "C": float("inf")
}
but the function must work with any graph.
Important catch
An exit/destination may have no outgoing edges, so it may not appear as a key in adjacency.

Think about how you will make sure every relevant node can still receive a distance.

Step 3 — previous
We need to reconstruct the final path.
Example:
previous:
B → A
C → B
exit1 → C
This means:
A → B → C → exit1
Use a dictionary.

Step 4 — visited
Keep track of nodes whose shortest known distance has been finalized.

For now:
visited = []
Do not optimize this yet.

Correctness first.

Step 5 — Main Dijkstra loop
The basic logic is:
while there are still nodes to process:

    find the unvisited node with the smallest distance

    if it is the destination:
        stop

    mark it as visited

    inspect its outgoing edges

    for each outgoing edge:

        calculate its travel time

        calculate the alternative total time
        through the current node

        if that route is better:

            update distances

            update previous

Step 6 — Edge travel time
For the first version, width is intentionally ignored.

Movement speed is a model-level parameter.

Use:

t = d / v

where:
- d = edge distance
- v = movement speed
- t = traversal time
Width will become important later when population and congestion are introduced.

Step 7 — Path reconstruction
Once the destination has been reached, use previous to work backwards.

Example:
exit1
  ↑
  C
  ↑
  B
  ↑
  A
Then reverse the result:
[A, B, C, exit1]
Return:
(path, total_time)
